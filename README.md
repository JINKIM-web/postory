# POSTORY — One Story. Every Channel.

사진 몇 장과 짧은 메모로 네이버 블로그·Facebook·Instagram·YouTube Shorts에 바로 올릴 콘텐츠를 만드는 웹앱입니다.
기획·설계 문서는 [docs/](docs/)에 있습니다 (명세서 v1.1, 개발계획서 v1.0, 구현순서 v1.0).

## 실행

```bash
npm install
npm run dev:api   # AI API 서버 → http://localhost:8787
npm run dev:web   # 웹앱 → http://localhost:5180
```

브라우저에서 http://localhost:5180 을 엽니다. (5173은 다른 로컬 프로젝트와 겹쳐서 5180을 씁니다.)

- `OPENAI_API_KEY`가 없으면 **데모 모드**로 동작합니다. AI 대신 입력한 근거 문장을 재배치해 전체 흐름을 확인할 수 있습니다 (상단에 "데모 모드" 표시).
- 실제 AI를 쓰려면 `apps/api/.env.local`의 `OPENAI_API_KEY`에 키를 넣고 API 서버를 다시 시작합니다 (이 파일은 Git에 올라가지 않습니다. 변수 목록은 `.env.example` 참고). 모델은 `OPENAI_MODEL_LIGHT`(분류·점검)와 `OPENAI_MODEL_MAIN`(본문 작성)으로 바꿀 수 있습니다.
- 스톡 이미지 검색은 `PIXABAY_API_KEY` 또는 `UNSPLASH_ACCESS_KEY`가 있을 때만 나타납니다. 블로그 대표 카드의 Unsplash 검색도 `UNSPLASH_ACCESS_KEY`가 필요하고, 출처 링크의 앱 이름은 `UNSPLASH_APP_NAME`으로 바꿀 수 있습니다.
- env 파일은 서버 코드가 직접 읽습니다 (우선순위: 실행 환경 > `.env.local` > `.env`). 키가 있어도 `POSTORY_MOCK=1`로 실행하면 데모 모드이며, `npm test`는 항상 이 모드로 돌아 OpenAI 비용이 나가지 않습니다.

```bash
npm test          # 규칙 엔진·스키마·Mock 파이프라인 테스트
npm run typecheck
```

## 구조

```text
apps/web          React + Vite + Tailwind + TipTap. 모든 데이터 저장과 생성 단계 진행을 담당
apps/api          Express. 상태 없는 AI 프록시 (OpenAI 키는 이 서버에만 둠)
packages/shared   Zod 스키마·타입, API 계약, platform-rules.json
packages/quality  규칙 기반 품질 점검(금칙어·Claim·상투 표현·키워드·길이·협찬 표기), 텍스트 유틸
```

## 로컬 MVP에서 계획서와 달라진 점

| 계획서 | 로컬 MVP | 이유 |
|---|---|---|
| Supabase (Postgres·Storage·Auth·RLS) | **IndexedDB**(프로젝트·사진 Blob·버전·이슈·로그) + **localStorage**(설정·화면 상태) | 로컬 저장소로 MVP 진행 요청 |
| 로그인 | 없음 (브라우저 = 한 명의 사용자) | 서버에 사용자 데이터가 없음 |
| 서버 SSE로 단계 진행 | 브라우저가 6단계 API를 순서대로 호출하고 단계마다 IndexedDB에 저장 | 실패한 단계부터 재개 가능, 서버 상태 불필요 |
| 서버에서 sharp로 리사이즈·EXIF 제거 | 브라우저에서 canvas 재인코딩 (EXIF·GPS 전부 제거, 촬영일시만 먼저 추출) | 원본이 서버로 가지 않음 |
| pnpm | npm workspaces | 이 PC에 pnpm 없음 |

AI 호출만 API 서버를 거칩니다. 분석할 때 사진은 긴 변 1024px 저해상도 사본만 전송되며, 서버는 아무것도 저장하지 않습니다.

## MVP 범위 구현 현황 (Phase 1A + 1B + 1C)

- **입력**: 사진 1~10장(드래그 순서 변경·캡션), Quick Text, Category/Goal/Tone/Platform, 광고·협찬 체크, 자동 저장
- **AI 파이프라인**: 사진 분석(Visual Fact·신뢰도·얼굴 감지) → 기억 정리(사실/의견 분리) → 부족한 정보 확인(Smart Question 0~4개, EXIF 촬영일 확인, 업종 추정·확인) → Master Story → 채널별 작성 → 품질 검토
- **품질 엔진**: ① 규칙 점검 → ② 문맥 검토(LLM) → ③ 문제 문장만 재작성 → ④ 재검증. L1·근거 없는 문장은 자동 수정, 나머지는 추천 수정·무시, 자동 수정도 되돌리기 가능
- **편집**: 블로그 리치 편집기(소제목·굵게·목록·인용·사진 마커 이동/삭제), 제목 후보, 섹션 재작성(다시 쓰기·더 짧게·더 자연스럽게·정보 보강), Facebook·Instagram(해시태그·사진 순서)·Shorts(장면 편집·9:16 미리보기) 화면, 버전 기록·되돌리기
- **출력**: 네이버용 Rich/Plain 복사, 사진 번호를 맞춘 ZIP(EXIF 제거본, 출처.txt), .txt, 게시 준비·게시 완료 표시
- **관리·측정**: 라이브러리(검색·필터·복제·삭제), 사용량 한도(월·일·재작성), EventLog·UsageLog, Copy-ready Rate 등 지표(설정 화면)
- **1C**: 검색 품질 체크리스트, 키워드 반복, AI 상투 표현, 민감 업종 사전, Publish Readiness(설정에서 표시 여부 선택), 스톡 이미지(Pixabay 저장 / Unsplash URL·다운로드 추적·출처 표기), 반응형

## Phase 2A — Personalization (명세서 21·22장, 11장 L4)

사이드바 **내 보이스 · 브랜드**에서 관리하고, 새 스토리 입력 화면의 **개인화** 카드에서 프로젝트마다 고릅니다.

- **My Voice**: 내가 쓴 글 2~5개에서 문장 길이·말투·자주 쓰는/피하는 표현·문단·CTA 스타일을 분석. 적용하면 선택 톤보다 내 문체를 우선하고, 품질 검토의 톤 항목이 "My Voice 일치"로 바뀝니다.
- **브랜드 프로필**: 소개·제품은 사용자가 등록한 사실(근거 분석에 "브랜드 프로필")로 쓰이고, 업종 태그는 민감 업종 사전에, 브랜드 금칙어·선호 표현은 생성과 검사에 적용됩니다.
- **내 금칙어(Level 4)·선호 표현**: 모든 콘텐츠에 적용. 금칙어는 생성 시 피하고, 품질 검사에서 "내 금칙어"로 표시하며 대체어가 있으면 추천 수정을 만듭니다.
- **콘텐츠 메모리**: 자주 쓰는 CTA(지난 글의 CTA를 저장 제안), 제품·서비스 정보. 고른 CTA는 마무리에 그대로, 제품 정보는 확인된 사실로 들어가고 사용 횟수 순으로 정렬됩니다.
- 저장 위치: IndexedDB v2 (`voiceProfiles`, `brandProfiles`, `userWords`, `memoryItems`). 기존 데이터는 그대로 업그레이드됩니다.

## 블로그 대표 카드 이미지

블로그 스튜디오 맨 위에서 대표 카드를 만듭니다. 대표 사진(기본: 직접 찍은 첫 사진) 또는 Unsplash 검색 이미지 위에 제목·보조 문구를 얹어 4:3 / 1:1 / 16:9, 어두운/밝은 글자 배경으로 그립니다.

- 네이버 복사 본문 맨 위에 `[대표 카드 이미지 삽입]` 자리가 들어가고, 이미지 ZIP에 `00_대표카드.jpg`로 포함됩니다 (개별 다운로드도 가능).
- Unsplash 이미지는 고를 때 다운로드 추적 엔드포인트를 호출하고, 카드 위·복사 본문·`출처.txt`에 "Photo by 작가 on Unsplash"를 링크와 함께 표기합니다. 참고 이미지이므로 실제 방문·사용 사진처럼 소개하지 않도록 안내합니다 (명세서 8.3).

## 아직 확인하지 못한 것

- **실제 OpenAI 응답 품질**: 키가 없어 데모 모드로만 끝까지 검증했습니다. 키를 넣은 뒤 골든셋(계획서 6.2)으로 근거 없는 문장 비율을 확인해야 합니다.
- **네이버 스마트에디터 붙여넣기**: 클립보드에 들어가는 HTML은 확인했지만, 실제 에디터에서 서식이 어떻게 남는지는 PoC(명세서 15.4)가 필요합니다. 그 전까지 소제목은 "큰 굵은 글씨"로 변환하는 옵션을 기본으로 켰습니다.
- **HEIC**: 브라우저가 디코딩할 수 있을 때만 됩니다 (Safari 외에는 JPG로 변환 안내).
- **스톡 이미지 API**: 키가 없어 실제 검색은 호출해 보지 않았습니다.
- 금칙어 사전·광고 표기 문구는 법률 검토 전 초안입니다 (미결 #9).
