## 1. 개발 계획 한눈에 보기

### 1.1 목표
사진 몇 장과 짧은 메모만으로 **수정 없이 게시할 수 있는 콘텐츠**를 만드는지 검증한다. 핵심 지표는 **Copy-ready Rate 60% 이상**, **입력에 없는 사실(Unsupported Fact) 2% 이하**다.

### 1.2 단계와 일정

| 단계 | 기간 | 결과물 | 마일스톤 |
|---|---|---|---|
| Phase 0 사전 검증 | 2026-10-05 ~ 10-16 (2주) | 네이버 붙여넣기 PoC, 비용 측정, 호스팅·모델 결정, 개발 환경, 골든셋 | M0 (10/16) |
| Phase 1A 사진 → Blog | 10-19 ~ 12-04 (7주, S1~S4) | 업로드부터 블로그 생성·품질 검토·네이버 복사까지 | **M1 내부 데모 (12/4)** |
| Phase 1B 멀티채널 | 12-07 ~ 12-25 (3주, S5~S6) | Facebook / Instagram / Shorts 스크립트 | **M2 클로즈드 알파 (12/25)** |
| Phase 1C 품질 고도화 | 12-28 ~ 2027-01-15 (3주) | 검색 품질·상투 표현·민감 산업, 모바일, 사용량 한도, 스톡 이미지 | — |
| 안정화·베타 | 2027-01-18 ~ 01-29 (2주) | 오픈 베타 30~50명, 법률 검토 반영 | **M3 MVP 출시 (2027-02-01)** |
| Phase 2 | 2027 Q1 후반 ~ Q3 | My Voice, 자동 게시, 영상, 분석 | 베타 후 재수립 |

### 1.3 구현 원칙
1. **공통 스키마를 먼저 만든다.** Category·Goal·Tone·Platform 같은 값과 Master Story·Evidence·Quality Issue 구조를 `packages/shared`에 Zod로 먼저 정의한다. 프론트·백엔드·AI 작업이 모두 여기에 의존한다.
2. **뼈대를 먼저 끝까지 잇고, 속을 나중에 채운다.** 생성 파이프라인은 가짜 단계로 SSE·저장·재개를 먼저 완성한다. 그러면 프론트(처리 화면)와 AI(각 단계 구현)가 동시에 작업할 수 있다.
3. **Copy를 일찍 만든다.** 핵심 지표가 "복사"이므로, 품질 엔진보다 먼저 "생성 → 편집 → 복사"를 끝까지 연결해 실제 사용 흐름을 확인한다.
4. **규칙 기반 점검은 병렬로 만든다.** 금칙어·Claim·길이 점검은 LLM 없이 동작하는 순수 함수라서 S2부터 따로 만들고 S4에 연결한다.
5. **AI 변경은 골든셋으로 확인한다.** 프롬프트·모델·사전을 바꿀 때마다 골든셋 평가를 돌린다 (계획서 6.2).

## 3. 핵심 경로와 병렬 작업

### 3.1 핵심 경로 (지연되면 M1이 밀리는 순서)
```text
공통 스키마(1) → DB·RLS(2) → 업로드(4) → LLM 계층(8) → 파이프라인 뼈대(9)
→ 1~3단계(11) → Master Story(14) → Blog Writer(15) → 에디터(16) → 복사(17)
→ 품질 검토(19) → M1
```

| 스프린트 | Frontend | Backend | AI/풀스택 | 디자인 |
